## 4. Code quality across the milestone

Thermo-nuclear review of the four L3 PRs' first-parent diffs (#132, #146, #162, #164; base
`ce4020f`, the other lanes' merges in that range excluded), read against `95adf87`,
2026-11-26: **BLOCKED under the skill's strict bar, B−; no correctness or constraint 1
problem.** Report (git-ignored, main checkout):
`docs/code-quality/thermo-nuclear-review-2026-11-26-laplace3d-L3-gate.md`, with a seven-step
ordered plan. Read only; no build or test run by the reviewer. No file passes 1,000 lines
(`transfer.rs` fell 973 → 336 in CL3.3; `dataset.rs` 594, `dataset3d.rs` 370).

The three blockers are one finding, duplication by the "duplicates an existing
implementation" rule:

1. `dataset3d.rs:39–216` mirrors `dataset.rs:84–286`: `Split3d`, `generate_3d`,
   `label_check_3d`, `write_split_3d` beside `Split`, `generate`, `label_check`,
   `write_split`.
2. CL3.4's `SidecarFacts` (`dataset.rs:290–309`), nine fields filled by both writers,
   exists because `Split` and `Split3d` are separate types.
3. `Poisson3dSet` (`catalogue.rs:82–104`) is `PoissonSet` with another prefix.

Much of this follows from decisions already taken: D1 routes rank 2 to the existing code,
and the L2 gate's Q2 kept the 2D `label_check` body; CL3.4 was scoped to the sidecar
constructor (CL3.2 review F2 not taken). The gate PR carries no code, so they become Q1 below.

Other findings:

4. **No exact test of the 2D generator's `f` and `u`** (`dataset.rs` tests): the 2D
   sidecar bytes and the 2D loader are pinned bit for bit, `generate()`'s arrays only to
   tolerances. Any merge of finding 1 needs that oracle first (constraint 1, D2).
5. **2D and `_nd` twins in `transfer.rs:264–332`** and the CC norms: the `_nd` forms are
   proven identical at rank 2 (`rank_two_is_bit_identical_to_2d`); the 2D bodies could go.
   `_nd` also means "any rank" in `chebyshev` but "2D or 3D" in `metrics::poisson`.
6. **3D naming and the loader seam:** three spellings (`_3d`, `poisson3d_`, `*3d` modules);
   `load_poisson3d_cheb_field` returns `ArrayD` where the 2D reader returns `Array3`; no CI
   test writes a 3D split and loads it back (only the ignored n = 65 measurement does).
7. **`examples/generate/poisson3d.rs:57–63`** hard-codes `k: None`; safe today because
   `poisson3d_names` pins `GENERATED_3D` at K(n), but a catalogued set with K ≠ K(n) would
   be written at K(n) under the wrong name. A shared set type (finding 3) removes it.
8. Lower: `grf3d` restates `grf`'s spectrum code (optional, only with finding 1's
   trait); the sidecar does not record its dimension (a 3D sidecar parses as 2D);
   `pde/poisson` imports `SidecarRecord` from the loader layer (before L3, two users now);
   `chebyshev::tensor` and `transfer` import each other; test helpers copied between
   sibling test modules.

## 9. Retrospective on the loop

- **A task's machine was not checked at planning.** CL3.2 planned n = 65 on the VM (D8); the
  VM's `datagen` build failed twice at run time (libclang, then FFTW), and the set moved to
  the Mac. `/next-task` could build the task's example on the named machine during planning
  (with the author's go for the VM) rather than at the run.
- **Review findings as follow-up tasks.** CL3.2's review F1 (one sidecar constructor) became
  CL3.4, a separate PR because it edited a 2D function body and needed the author's go. That
  kept constraint 1 visible, at the cost of one more PR of about 150 lines; worth keeping for
  2D edits, not for 3D-only ones.
- **The code-quality review caught duplication across tasks.** CL3.3's review blocked once
  (the 3D readers copied the 2D ones) and the fix shared one body between 2D and 3D. The
  roadmap's *Done when* for later `_3d` siblings could say "shares the 2D body where
  constraint 1 allows" up front.
- What worked: the measurement asked for at the L1 gate (error 2 in 3D against 2D) went into
  CL3.3's *Done when* and came back with numbers; gate questions folded into the next task's
  first commit (L2 Q2) landed without a separate PR.
