## 5. Measured numbers against the proposal

L1 has no cost estimates to check (proposal §7 is L0's). What it measured against the
proposal's expectations:

- Proposal §6 expected one apply-along-an-axis helper serving rank 3. `apply_nd` does it as
  T₀ along axis 0 as one matrix product, then recursion on each slice; the CC norms read a
  field as `[n₀, rest]` with the Kronecker product of the other weights, so the 2D scaling
  serves every rank. Both met their closed forms to 1e-14 (the transfers on
  separable fields, and the polynomial integrals, which are exact in exact arithmetic).
- Error 5 in 3D (proposal §3.5): the six-face sum reproduces the 24/8 RMS against closed
  forms, and at rank 2 the same face formula reproduces `boundary_errors` to 1e-14, so the
  3D definition is a consistent extension of the 2D one.
- Size: `chebyshev/transfer.rs` reached 973 lines in CL1.2 (the roadmap says 970); `metrics/poisson.rs` passed
  1,000 lines in CL1.3 and was split into `poisson/{mod,tests}.rs` (blocking review finding).
  The proposal said nothing about size; the one-PR-per-task limit held (CL1.3 918 lines
  added, its largest).

## 9. Retrospective on the loop

- **File size seen too late.** CL1.2 left `transfer.rs` at 973 lines and noted it; CL1.3
  was blocked in review for passing 1,000 and split the file then. `/next-task`'s planning
  step could list the files the task will touch with their line counts, and plan the split
  as the task's first commit when one would pass 1,000.
- **Cross-task CONVENTIONS edits.** The Verification list was a follow-up in two PRs and
  needed a gate to land. A task that implements a CONVENTIONS statement could add its test
  names to the Verification list in its own PR (a docs line, signed off with the PR), so
  the gate only checks it.
- **Duplicate test names across modules** (`rank_two_is_bit_identical_to_2d` twice) make
  CONVENTIONS' bare-name lists ambiguous and the exact filter error-prone (the full path is
  needed anyway). `/verify` could list the D2 tests it ran by full path.
- What worked: D2's in-process oracle pattern made constraint 1 cheap to show in every PR,
  and L1's three tasks each stayed inside their named modules.
